# Skill: answer

The other half of «Ask backend» / «Ask frontend». The dev pastes the question (a short message, the
brief for Claude, or both); Claude answers from **this** repo's code. Read-only — nothing is changed.

House rules (language = the dev's language; one screen; nothing left open) →
[`../_shared/house-rules.md`](../_shared/house-rules.md).

## Protocol

1. **Understand the question.** Pull out what exactly is asked (a field, an error, a state, a flow,
   a limit) and in what format the asker wants it. Ambiguous → one `AskUserQuestion` to the dev, with
   Claude's reading first.
2. **Find it in the code.** Grep/Read yourself; dispatch [`explorer`](../../agents/explorer.md) only
   when the question names nothing concrete. Prefer facts that come from code — the serializer / DTO
   that shapes the response, the validator, the state enum, the error mapping — over docs. A local API
   contract (Swagger / OpenAPI from this repo) may be used per [`../_shared/inputs.md`](../_shared/inputs.md).
3. **Not in the code yet** (the feature doesn't exist, the decision isn't made) → say so plainly and
   give the options with Claude's recommendation; the dev picks before sending (one `AskUserQuestion`).
4. **Write two answers** and show them to the dev:
   - **Short — for the person**: 3–6 lines, plain words, the decision / fact first, no code.
   - **Detailed — for their Claude**: one fenced block: the answer; the contract (endpoint, method,
     request / response schema, error codes, pagination, nullability); a JSON example of each relevant
     response; edge cases and states; environment differences if any (works differently in prod / stub
     mode); `file:line` references for the asker's dev to trust it.
5. If the answer exposed a rule worth keeping, offer one line to add to the context's `language.md`
   (invariant or `## External constraints`).

## Definition of Done

- Both answers are grounded in `file:line` facts or explicitly marked as "not decided yet" with options.
- Nothing in the repo was modified (except an agreed `language.md` line).
- Grounding every claim in code is this skill's **structural self-check**
  ([`../_shared/house-rules.md`](../_shared/house-rules.md)).

## Anti-patterns

- **Answering from memory or docs when the code says otherwise.**
- **A long answer for the person** — the detail belongs in the block for their Claude.
- **Changing code** to make the answer true — that's a `small-task`.
